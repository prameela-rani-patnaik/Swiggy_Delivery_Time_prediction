# Monitoring stack (Prometheus + Grafana) for the webinar demo

Built for `docs/webinar_post_model_lifecycle`'s Monitoring section and WOW #6 ("the alarm that
never sleeps"). Runs alongside the API (the app itself runs outside this compose file — either
directly with `python app.py` or as its own `docker run`, per `DEMO_RUNBOOK.md`), and reaches it
via `host.docker.internal:8000`. This works identically whether you're rehearsing locally on a
Mac/Windows laptop (Docker Desktop) or running for real on the EC2 Linux box — `network_mode:
host` was tried first and rejected because it only behaves that way on native Linux, not on
Docker Desktop, which would have made local rehearsal silently fail to connect.

## What's here

- `docker-compose.yml` — Prometheus + Grafana containers.
- `prometheus.yml` — scrape config pointed at the app's `/metrics` endpoint.
- `grafana/provisioning/datasources/` — auto-registers Prometheus as Grafana's data source.
- `grafana/provisioning/dashboards/` + `grafana/dashboards/` — auto-loads the
  "Swiggy Delivery Time API" dashboard (request rate, p95 latency, out-of-distribution request
  count and rate).
- `grafana/provisioning/alerting/rules.yml` — auto-loads an alert rule that fires when any
  out-of-distribution request is seen in the last 5 minutes.

## Setup (do this before the webinar, not during)

1. Deploy the app as normal on port 8000 (see `docs/webinar_post_model_lifecycle/DEMO_RUNBOOK.md`)
   — it exposes Prometheus metrics at `:8000/metrics`, including the custom `ood_requests_total`
   counter (see `app.py`'s `is_out_of_distribution` check, backed by `models/feature_bounds.json`,
   generated by `scripts/compute_feature_bounds.py`).
2. Copy this `monitoring/` folder onto the same machine running the app (EC2, or your laptop for
   rehearsal).
3. `cd monitoring && docker compose up -d`
4. Confirm Prometheus is scraping successfully: `http://<HOST>:9090/targets` — the
   `swiggy-time-api` job should show state `UP`. If it shows `DOWN` with a connection refused,
   confirm the app is actually listening on `0.0.0.0:8000` (not `127.0.0.1:8000`) on the host.
5. Confirm Grafana loaded the dashboard and datasource automatically:
   `http://<HOST>:3000` → login `admin` / `admin` (change the password) → Dashboards →
   "Swiggy Monitoring" folder → "Swiggy Delivery Time API".
6. Confirm the alert rule loaded: Alerting → Alert rules → "Out-of-distribution prediction
   requests spiking" should be listed with state `Normal`.
7. Send one out-of-distribution request (see the payload in `DEMO_RUNBOOK.md` § Monitoring) and
   confirm the alert flips to `Pending` then `Firing` within ~1 minute, and the dashboard's OOD
   panels move. This is the dry run for WOW #6 — do it at least once before the room fills up.

## Cleanup after the webinar

```bash
cd monitoring
docker compose down
```
Also stop/terminate the demo EC2 instances and delete the load balancer + target group from the
earlier section if they were created only for this demo, to avoid ongoing AWS cost.
